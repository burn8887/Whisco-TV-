# Migration to `burn8887/salim-drive` — 20 October 2026

Salim now lives in its own private repository. This capsule is the **archive** of how it was
built, not the working copy.

## Target repository

| | |
| --- | --- |
| Repository | `burn8887/salim-drive` (private) |
| Default branch | `main` |
| Source of truth | `salim-workspace/tools/promote.py` in this repository |
| Regenerate | `python3 salim-workspace/tools/promote.py --output <dir> --verify` |

The migrated tree is **not** a hand-copied directory. It is generated by `promote.py`, which
rewrites identifiers and paths, drops the capsule-only scaffolding, and then checks its own
output. A workspace reset costs one command, not the project.

## What was deleted, not ported

- `tools/materialize.py` and `test_materialize.py` — builds run in place.
- `tools/verify_isolation.py` — there is no host application to protect.
- Every `.source` suffix — the host scanner cannot see the new repository.
- The self-ignoring `.gitignore` (`*`).

## Permanent identity change

`app.salim.android.demo` / `app.salim.ios.demo` → **`com.salimdrive.app`** for both platforms.
Kotlin packages are now `com.salimdrive.app` and `com.salimdrive.core`. Versions went to
`0.3.0` / code `3`. This must be settled **before** the first Play or App Store upload, because
neither identifier can change afterwards.

## Blocker at hand-off

The sandbox GitHub connection still returns **403 "Write access to repository not granted"** for
`salim-drive`, even after the repository was selected for the installation, so the push has to
come from a machine with ordinary write access. The generated tree is committed locally and also
packaged as a git bundle (`salim-drive-migration.bundle`) for manual import:

```sh
git clone -b main salim-drive-migration.bundle salim-drive
cd salim-drive
git remote set-url origin https://github.com/burn8887/salim-drive.git
git push -u origin main
```
