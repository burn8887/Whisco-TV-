# Project history

Salim did not start as its own repository. This page records where it came from, what
changed, and which claims are backed by evidence — so the history survives even if no chat
transcript does.

## 1. Origin: a capsule inside an unrelated app repository

Salim had to be developed while its owner's GitHub access was limited to a single repository,
`burn8887/Whisco-TV-`. To avoid touching Whisco TV in any way, every Salim file was kept under
`salim-workspace/` with build files renamed (`*.source`) so the host project's scanner would
ignore them. The host application's own sources, workflows, secrets and store records were
never modified.

The temporary application identifiers were `app.salim.android.demo` and `app.salim.ios.demo`,
chosen because `salim.com` belongs to someone else and no Salim-owned domain was live yet.

Salim work was merged into the host repository through pull request #32 (merge commit
`82a6fc5`): 96 additions, no host file modified. The capsule archive is 93 files.

## 2. Native evidence, and its exact scope

Two GitHub Actions runs proved the native code compiled and its tests passed **in the capsule
layout**:

- **iOS** — run [39418444930](https://github.com/burn8887/Whisco-TV-/actions/runs/39418444930),
  source `b790ebe`: Xcode 26.3, iPhone 16 Pro / iOS 18.5 simulator, **9 XCTest cases passed,
  0 failed, 0 skipped**, plus an unsigned arm64 device archive. Artifact
  `salim-ios-simulator`, retained 14 days. No signing, IPA export, TestFlight processing or
  physical-device verification.
- **Android** — run [39418531146](https://github.com/burn8887/Whisco-TV-/actions/runs/39418531146),
  source `829c630`: **24 JUnit cases passed** (14 JVM engine/sync, 6 SQLite, 4 native
  lifecycle) on an API 35 emulator, APK ZIP alignment verified at 16 KB, and 16,384-byte ELF
  LOAD alignment for arm64-v8a and x86_64. That is static packaging evidence, not a physical
  16 KB-page device. The release AAB is unsigned.

Neither run is a store upload, a TestFlight build or a signed release. Neither run was
repeated after the move to this repository's layout — no Android SDK, Xcode or macOS runner is
available in the environment where the tree is prepared.

## 3. Rename to the permanent identity

On 20 October 2026 the owner approved:

- permanent bundle identifiers **`com.salimdrive.app`** (Android `namespace` and
  `applicationId`, iOS `PRODUCT_BUNDLE_IDENTIFIER`);
- repository name **`salim-drive`**, private;
- store title **“Salim — Road Awareness.”**

Neither identifier has been registered in Google Play or App Store Connect yet.

## 4. Move to this repository

The Salim tree was migrated to `burn8887/salim-drive` in the layout documented in `README.md`.
The migration is not a hand-copied directory: it is generated by `tools/promote.py` in the
source repository, which rewrites identifiers and paths, drops the capsule-only scaffolding
(`materialize.py`, `verify_isolation.py`) and then checks its own output. Losing a workspace
costs one command, not the project.

The generated tree is verified before it is committed: the Python tool tests, the
three-workflow check, the site check, the browser engine tests and a production web build.

## 5. What is still not true

Recorded here so no later summary can quietly upgrade it:

- All alert data is fictional; no provider is connected.
- No app has been published, signed for distribution, or delivered to a tester.
- Background location, audio ducking, battery behaviour and accessibility have not been
  validated on a physical device.
- CarPlay, Android Auto, watchOS, vehicle automation and billing are not implemented.
- The signed-release workflow exists and is manual-only, but has never run with real
  credentials.
- `www.salimdrive.com` is not serving Salim yet, and the operator line on the site still
  reads as a placeholder.
